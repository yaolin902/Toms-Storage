# Tom's Storage – 1.7.10 backport (Inventory Connector + Storage Terminal)

Backport of `tom5454/Toms-Storage` (1.15 snapshot `dfa190b`, the 1.16 branch's crafting terminal, and the
storage terminal / connector / crafting terminal improvements up to the 2.4.2 code) to Minecraft 1.7.10, on top of the
[GTNH ExampleMod1.7.10](https://github.com/GTNewHorizons/ExampleMod1.7.10) build template
(RetroFuturaGradle). Included: Inventory Connector, Storage Terminal, Crafting Terminal.
The template's own README is kept as `docs/TEMPLATE_README.md`.

## Compiling in IntelliJ IDEA

1. **File > Open** and pick this folder (the one containing `build.gradle.kts`). Let IntelliJ import it as a Gradle project.
2. Gradle JVM: the template pins **JDK 25** for the Gradle daemon (`gradle/gradle-daemon-jvm.properties`).
   Gradle normally downloads it automatically. If it can't, install a JDK 25 and select it in
   *Settings > Build, Execution, Deployment > Build Tools > Gradle > Gradle JVM*.
   The mod itself still compiles to Java 8 bytecode (Jabel), which is what 1.7.10 needs.
3. First time only, in the Gradle tool window (or a terminal) run `./gradlew setupDecompWorkspace`.
   This downloads and deobfuscates Minecraft/Forge 1.7.10, so it takes a while and needs internet.
   After it finishes, hit **Reload All Gradle Projects** so IntelliJ sees the sources.
4. `com.tom.storagemod.Tags` is generated by the build (it holds the version). If IntelliJ shows
   it red before the first build, run `./gradlew build` once or `./gradlew classes`.
5. Build the jar: `./gradlew build` -> `build/libs/`. Test in-game: `./gradlew runClient`
   (or `runServer`). The template also creates matching run configurations in IntelliJ.

## Changes to the template

* `gradle.properties`: `modId = toms_storage`, `modGroup = com.tom.storagemod`, `modName`,
  `generateGradleTokenClass = com.tom.storagemod.Tags`, `usesMavenPublishing = false`,
  and **Spotless/Checkstyle disabled** (the code uses tabs; the template's formatter wants 4 spaces
  and would fail `build`). To re-enable: remove `disableSpotless`, then run `./gradlew spotlessApply`.
* Removed the example `com.myname.mymodid` classes, `CODEOWNERS`, and the template's LICENSE files
  (they carry the template author's copyright). **Add your own license.** The upstream mod's licence
  should also be checked before you publish this port.
* `mcmod.info` uses the template's placeholder format.
* `StorageMod` uses `Tags.VERSION` and `acceptedMinecraftVersions = "[1.7.10]"`.

## Blocks

All three blocks are in the creative tab "Tom's Simple Storage" (or `/give @p toms_storage:ts.crafting_terminal`).

* **Inventory Connector** - place it and put chests/furnaces/etc. touching it. Right-click it to see
  `free/total` slots and how many inventories it sees. Connectors are walls: one never scans through another.
  `config/toms_storage.cfg`:
  * `inventoryConnectorRange` (4-256, default 16)
  * `multiblockInv` - block ids (`modid:name`) that are crossed as one inventory
  * `blockedBlocks` / `blockedMods` - things the connector must ignore even if they have an inventory
* **Storage Terminal** - place it on a connector or directly on a chest, on any of the 6 sides. Reach: 6 blocks to
  open, 25% more to keep it open.
* **Crafting Terminal** - a storage terminal with a 3x3 grid that keeps its contents.
  A used-up grid slot is refilled from storage (optionally from your inventory) *before* container items
  (buckets...) are handled, so recipes keep going. Shift-click the result to craft up to a stack. The small X clears
  the grid (storage first, then your inventory, then the floor).
  Recipe: crafting tables in the corners, diamonds on the edges, a Storage Terminal in the middle.

## Terminal screen

Option buttons on the left (hover for details; hold **Shift** to cycle backwards): sort type, sort direction,
search mode, control scheme, ghost items, tall mode (+ pull-from-inventory on the crafting terminal).
All settings are saved per terminal. Hover the **i** in the corner for slot statistics.

* **Sort types**: amount, name, mod, space efficiency (items wasting the most slots first), item ID, item type
  (creative tab order).
* **Search**: `iron pick` = all words, `iron | gold` = either, `@mod`, `#oredict`, `$regex-on-NBT`; plain words match
  name and tooltip (regex ok). Right-click the box to clear. Modes: auto-focus, keep search.
* **Ghost items**: while Shift is held the list order is frozen and items that run out stay as a yellow `0`, so
  repeated shift-pulling doesn't make the grid jump around.
* **Tall mode**: the item grid grows to use the screen height.
* Counts are compact: 999, 1.2k, 12k, 1.5M (hover an item for the exact amount from 1000 up).
* AE controls (default): left click take stack / insert held; right click half (Ctrl = quarter);
  Shift+right one; Ctrl+Shift+right one straight to inventory; Shift+left stack straight to inventory;
  Space+click on empty area dumps your inventory; shift-click your own slots to insert.
  RS and vanilla schemes are selectable (hover the button).

## Performance work (from 2.4.2)

* Every inventory keeps a snapshot of its slots; a terminal asks "did anything change?" with one cheap comparison
  pass per tick and only rebuilds the item list after a real change. All viewers/terminals on a connector share this.
* The server only sends what changed (items get a small id, the item and its NBT are sent once, clicks use the id).
* Connector scans are spread over the 20-tick cycle per connector, reuse their inventory objects between scans, skip
  0-slot inventories and count a duplicated inventory once.
* The crafting terminal remembers the last matching recipe instead of searching every recipe each time.
* Display names, tooltips, ore names and NBT text used by sorting/search are cached.

## What differs from the original

| Original | 1.7.10 |
|---|---|
| Capabilities / `IItemHandler` | `IInventory` + `ISidedInventory` (sided inventories only expose the slots a hopper could reach on that side) |
| Blockstate JSON + models | Block metadata (6 mount directions), `setBlockBounds`, per-side textures |
| Terminal sync via menu data slots | `SimpleNetworkWrapper`; updates chunked under the 32 KB 1.7.10 payload limit |
| Recipe `getRemainingItems` | 1.7.10 container items (`getContainerItem`) |
| Item tags | Ore dictionary (`#` search) |
| Action-bar messages | Chat messages |
| Settings popup menu | Cycle buttons |

Terminals saved with the earlier single-number settings format are converted automatically on load.
Known cosmetic limits: terminals on top/bottom don't rotate their screen texture; no button click sound.

## Not ported

Everything you did not ask for (trims, open crate, cables, proxy, hopper, level emitter, paint kit, wireless
terminals, advancements) and what 1.7.10 has no equivalent for: the offhand slot, recipe book, JEI/EMI search sync
and recipe auto-fill (a NEI overlay handler would need the NEI jar as a dependency), and the multithreaded item
aggregation option (1.7.10 inventories aren't thread safe).

## Verification status

Not compiled against the real 1.7.10 sources by me (the build hosts were unreachable from where this was made).
Checked: every file parses; the logic (connector scan incl. stagger/blocklists/multiblock/range, snapshot change
tracking, network reuse, sync deltas, sorting, search language, settings migration, reach rules, crafting recipe cache,
refill/remainder handling, shift-craft cap, clear, NBT) runs against API stubs in 92 checks. The container, packets,
GUI and rendering are not exercised. If the build complains, the likeliest culprits are MCP-name differences in:
`drawHoveringText`, `updateHeldItem`, `mergeItemStack`, `GuiTextField` (`setCanLoseFocus`, `isFocused`, `setFocused`),
`EnumRarity.rarityColor`, `Block.getBlockFromItem`, `Slot.yDisplayPosition`, `EntityPlayerMP.playerNetServerHandler`,
`OreDictionary.getOreIDs`, `CreativeTabs.getTabIndex`.
